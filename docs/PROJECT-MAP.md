# TRL repository map

This map reflects the current repository layout. The generated site is served from the repository root by GitHub Pages.

| Path | Role | Edit guidance |
|---|---|---|
| `tools/build.py` | Python source for the generated website pages and shared offer/contact settings | Main source of truth for generated page content. Edit here, then rebuild. |
| `index.html`, `services.html`, `who-we-help.html`, `pricing.html`, `how-it-works.html`, `about.html`, `faq.html`, `contact.html`, `privacy.html`, `terms.html`, `404.html` | Generated static website pages | Preview build output; do not make a lasting content change only here. |
| `assets/css/style.css` | Website layout, responsive styles, colors, and typography rules | Edit for visual/layout changes, then preview at desktop and phone widths. |
| `assets/js/main.js` | Browser-side navigation, form, and interface behavior | Edit only for client-side behavior; check without relying on a local backend. |
| `assets/fonts/` | Self-hosted website font files | Keep files licensed for use and avoid adding unnecessary font weights. |
| `assets/img/` | Website favicon, app icon, and social/share artwork (`og-image.svg` source plus the deployed PNG) | Keep the green assets visually aligned; check rendered dimensions and file size when replacing. |
| `README.md` | Public-facing TRL/GitHub profile README | Keep client-facing; link to developer docs instead of turning it into a setup manual. |
| `trl-profile-banner.gif` | Approved animated profile hero | Preserve unless Rashid explicitly approves a redesign. |
| `trl-founder-card.png`, `trl-services.png`, `trl-process.png` | Static, lightweight supporting README cards | These replace lower-priority animated cards to reduce mobile downloads. |
| `trl-workflow.svg` | Lightweight illustrative workflow diagram, explicitly labeled as an example | Safe demo visual; it is not a client system or result. |
| `trl-cover.svg` | Standalone TRL brand-cover asset | Keep only if it remains useful; it is not part of the generated page build. |
| `docs/CASE-STUDY-TEMPLATE.md` | Blank, permission-first case-study drafting aid | Never add client details here; use a private copy and publish only after written approval. |
| `docs/LEAD-TRACKER-TEMPLATE.csv` | Empty enquiry-tracking header row | Copy to ignored `private-data/` before adding any real lead information. |
| `sitemap.xml`, `robots.txt`, `manifest.webmanifest`, `.nojekyll` | Generated/publication support files | Regenerated by `tools/build.py`; inspect the diff after each build. |
| `CHANGELOG.md` | Human-readable release history | Add a short entry for approved changes. |
| `.gitignore`, `.editorconfig`, `.gitattributes`, `LICENSE` | Repository configuration and licensing | Do not put private client records or local credentials into the repository. |
| `.well-known/security.txt` | Public security contact/policy metadata | Keep current and free of private credentials. |

## Build outputs

`tools/build.py` writes the HTML pages listed above, plus `sitemap.xml`, `robots.txt`, `manifest.webmanifest`, and `.nojekyll`. The source code and public README are maintained separately: the Python builder does not generate `README.md`.

## Deployment path

The current recorded deployment is GitHub Pages from `main` at the repository root. Verify **Settings → Pages** if the branch/folder configuration changes. A commit on another branch is only a review copy until the approved changes reach the configured Pages source.
